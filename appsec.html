App Security

Penetration Testing of the Insecure and Vulnerable DVIA App

The Project

What is this assessment?

This project presents a security assessment of the Diva mobile application, a purposely vulnerable Android APK used for security training. The assessment simulates real-world attacks to identify, exploit, and document mobile security vulnerabilities.

The assessment followed a Black Box methodology, approach, simulating an external attacker with no prior knowledge of the application to evaluate its security defenses.

The evaluation identified and analyzed the 8 most critical vulnerabilities, documenting each with proof of concept, impact, and remediation recommendations.

Key Findings

Vulnerabilities Discovered

Critical

SQL Injection

Unsanitized queries allowed extraction of all user records with a single malicious input.
Critical

Native Code Buffer Overflow

Unsafe strcpy() usage in a native library allowed crafted input to crash the app and reveal hidden logic.
High

Access Control Issues

PIN verification relied only on an intent extra, bypassed via ADB to expose API credentials.
High

Hardcoding Issues

A secret key embedded in plaintext source code allowed a full security-check bypass.
High

Insecure Logging

Credit card numbers were written to system logs in plaintext via Log.e(), extractable through logcat.
High

Insecure Data Storage

Third-party credentials were stored unencrypted in SharedPreferences, readable via ADB.
